মডিউল 10 — *args এবং **kwargs

যেকোনো সংখ্যক আর্গুমেন্ট গ্রহণ করতে পারে এমন ফাংশন লেখা।

পূর্বশর্ত: মডিউল ০৫ — ফাংশন

এই লেসন শেষে আপনি যা করতে পারবেন

  • *args দিয়ে যেকোনো সংখ্যক positional আর্গুমেন্ট গ্রহণ করা
  • **kwargs দিয়ে যেকোনো সংখ্যক নামযুক্ত আর্গুমেন্ট গ্রহণ করা
  • সাধারণ, *args, ও **kwargs প্যারামিটার সঠিক ক্রমে সাজানো

ধারণা ও সিনট্যাক্স

কখনো কখনো একটি ফাংশনের কতটা আর্গুমেন্ট লাগবে তা আগে থেকে জানা থাকে না — যেমন একটি sum_all() ফাংশনের কথা ভাবুন যেটা 2টি সংখ্যা দিয়েও চলবে, 20টি দিয়েও। *args যেকোনো সংখ্যক অতিরিক্ত positional আর্গুমেন্ট একটি টাপলে জমা করে; **kwargs যেকোনো সংখ্যক অতিরিক্ত নামযুক্ত আর্গুমেন্ট একটি ডিকশনারিতে জমা করে। args ও kwargs নামগুলো আসলে প্রথা মাত্র — অ্যাস্টেরিস্কগুলোই আসলে গুরুত্বপূর্ণ।

সিনট্যাক্স
def func(a, b, *args, **kwargs):
    print(a, b)
    print(args)      # অতিরিক্ত positional args-এর tuple
    print(kwargs)     # অতিরিক্ত keyword args-এর dict

উদাহরণ

*args মৌলিক ধারণা খুব সহজ

*args মৌলিক ধারণা
def total(*numbers):
    return sum(numbers)
 
print(total(1, 2))
print(total(1, 2, 3, 4, 5))
আউটপুট3 15

numbers পাস করা যত positional আর্গুমেন্টই থাকুক তা ধরে রাখা একটি টাপলে পরিণত হয় — sum() যতগুলোই থাকুক না কেন সবগুলো যোগ করে দেয়।

সাধারণ প্যারামিটারের সাথে *args সহজ

সাধারণ প্যারামিটারের সাথে *args
def describe(name, *hobbies):
    print(f"{name} enjoys: {', '.join(hobbies)}")
 
describe("Ada", "chess", "coding", "reading")
আউটপুটAda enjoys: chess, coding, reading

name সবসময়ের মতো প্রথম আর্গুমেন্ট নেয়; বাকি প্রতিটি positional আর্গুমেন্ট hobbies টাপলে চলে যায়।

**kwargs মৌলিক ধারণা মধ্যম

**kwargs মৌলিক ধারণা
def build_profile(**details):
    for key, value in details.items():
        print(f"{key}: {value}")
 
build_profile(name="Ada", role="Engineer", city="London")
আউটপুটname: Ada role: Engineer city: London

details পাস করা প্রতিটি keyword আর্গুমেন্টের একটি ডিকশনারিতে পরিণত হয়, যা কলারকে ইচ্ছামতো নামযুক্ত ফিল্ড দেওয়ার সুযোগ দেয়।

দুটো একসাথে ব্যবহার করা বাস্তব উদাহরণ

দুটো একসাথে ব্যবহার করা
def order(item, *extras, **notes):
    print("Item:", item)
    print("Extras:", extras)
    print("Notes:", notes)
 
order("Burger", "cheese", "bacon", spicy=True, delivery="ASAP")
আউটপুটItem: Burger Extras: ('cheese', 'bacon') Notes: {'spicy': True, 'delivery': 'ASAP'}

প্যারামিটারের ক্রম গুরুত্বপূর্ণ: প্রথমে সাধারণ প্যারামিটার, তারপর *args, তারপর **kwargs — Python ফাংশনের সিগনেচারে এই ক্রম বাধ্যতামূলক করে দেয়।

ভিজ্যুয়াল ব্যাখ্যা

💡 এটা কেন কাজ করে?

উপরের ধারণার ব্যাখ্যাটি আবার ধীরে ধীরে, লাইন বাই লাইন পড়ুন — সেখানকার প্রতিটি কিওয়ার্ড উদাহরণের কোডের একটি লাইনের সাথে সরাসরি মিলে যায়। এখনো পরিষ্কার না হলে, এই লেসনে ট্রেসড উদাহরণ থাকলে সেটি এক ধাপ এক ধাপ করে আবার চালিয়ে দেখুন।

🔍 ভেতরে ভেতরে কী ঘটে? (অ্যাডভান্সড)

ভেতরে ভেতরে, Python আপনার সোর্স কোডকে বাইটকোডে কম্পাইল করে এবং একটি ভার্চুয়াল মেশিনে (CPython ইন্টারপ্রিটার) চালায়। ভ্যারিয়েবলগুলো একটি নেমস্পেস ডিকশনারিতে থাকা নাম, যা মেমরিতে থাকা অবজেক্টের দিকে নির্দেশ করে — উপরের ট্রেসারের মেমরি প্যানেলে ঠিক এটাই দেখানো হচ্ছে।

সাধারণ ভুল

✗ সাধারণ ভুল 1

ফাংশনের সংজ্ঞায় *args-কে **kwargs-এর আগে আসতে হবে, এবং কোনোটিই একটি আবশ্যক positional প্যারামিটারের আগে আসতে পারবে না।

✗ এটি এড়িয়ে চলুন
এতে দেখা দেবে SyntaxError: invalid syntax
def func(**kwargs, *args):
    pass
✓ সঠিক পদ্ধতি
সংশোধিত
def func(*args, **kwargs):
    pass
✓ ভালো অভ্যাস
  • *args/**kwargs তখনই ব্যবহার করুন যখন আর্গুমেন্টের সংখ্যা আসলেই পরিবর্তনশীল — যেখানে নামযুক্ত প্যারামিটার বেশি স্পষ্ট হতো সেখানে অতিরিক্ত ব্যবহার করবেন না।
  • একটি ফাংশন কী ধরনের অতিরিক্ত আর্গুমেন্ট প্রত্যাশা করে তা ডকুমেন্ট করুন, যদিও Python এটা বাধ্যতামূলক করবে না।
  • প্রয়োজনে my_func(*my_list, **my_dict) দিয়ে একটি বিদ্যমান লিস্ট/ডিকশনারি কলের ভেতরে unpack করুন।

3. একটি ফাংশন সিগনেচারে এগুলো কোন ক্রমে থাকতে হবে?

সারাংশ

  • *args একটি ফাংশনকে যেকোনো সংখ্যক অতিরিক্ত positional আর্গুমেন্ট, একটি টাপল হিসেবে গ্রহণ করতে দেয়।
  • **kwargs একটি ফাংশনকে যেকোনো সংখ্যক অতিরিক্ত নামযুক্ত আর্গুমেন্ট, একটি ডিকশনারি হিসেবে গ্রহণ করতে দেয়।
  • প্যারামিটারের ক্রম সবসময়: সাধারণ প্যারামিটার, তারপর *args, তারপর **kwargs।
