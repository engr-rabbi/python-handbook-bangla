মডিউল 15 — এরর ও এক্সসেপশন হ্যান্ডলিং

কী ভুল হতে পারে তা আগেই ভেবে রাখা, এবং ক্র্যাশ না করে সুন্দরভাবে ফেইল করা।

পূর্বশর্ত: মডিউল ১৪ — অবজেক্ট-ওরিয়েন্টেড প্রোগ্রামিং

এই লেসন শেষে আপনি যা করতে পারবেন

  • try/except দিয়ে এরর ধরা ও সামাল দেওয়া
  • try/except-এর পাশাপাশি else ও finally সঠিকভাবে ব্যবহার করা
  • raise দিয়ে নিজের এক্সসেপশন তৈরি করা
  • সাধারণ বিল্ট-ইন এরর টাইপ চিহ্নিত করা

ধারণা ও সিনট্যাক্স

একটি এক্সসেপশন হলো Python-এর "কিছু ভুল হয়েছে, এবং কীভাবে এগিয়ে যেতে হবে তা আমি জানি না" বলার পদ্ধতি। কোনো হ্যান্ডলিং না থাকলে, একটি এক্সসেপশন আপনার পুরো প্রোগ্রাম ক্র্যাশ করে দেয়। try/ except আপনাকে নির্দিষ্ট ব্যর্থতা — ভুল ইউজার ইনপুট, একটি অনুপস্থিত ফাইল, একটি নেটওয়ার্ক টাইমআউট — আগে থেকে ভেবে রেখে ক্র্যাশ না করে যুক্তিসঙ্গতভাবে সাড়া দিতে দেয়।

সিনট্যাক্স
try:
    risky_code()
except SomeError as e:
    handle_it(e)
else:
    only_if_no_error()
finally:
    always_runs()

উদাহরণ

মৌলিক try/except খুব সহজ

মৌলিক try/except
try:
    age = int("not a number")
except ValueError:
    print("That wasn't a valid number.")
আউটপুটThat wasn't a valid number.

ক্র্যাশ না করে, প্রোগ্রামটি ValueError ধরে ফেলে এবং একটি সহায়ক মেসেজ দিয়ে সাড়া দেয়।

এরর অবজেক্ট ধরা সহজ

এরর অবজেক্ট ধরা
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print("Error:", e)
আউটপুটError: division by zero

as e এক্সসেপশন অবজেক্টটি নিজেই ধরে রাখে, যা দিয়ে আপনি তার মেসেজ দেখতে বা লগ করতে পারেন।

else ও finally মধ্যম

else ও finally
try:
    number = int("42")
except ValueError:
    print("Invalid input")
else:
    print("Conversion succeeded:", number)
finally:
    print("Done attempting conversion.")
আউটপুটConversion succeeded: 42 Done attempting conversion.

কোনো এক্সসেপশন না ঘটলে else চলে; finally সবসময় চলে, এরর হোক বা না হোক — cleanup-এর জন্য উপকারী।

নিজের এক্সসেপশন তৈরি করা বাস্তব উদাহরণ

নিজের এক্সসেপশন তৈরি করা
def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("Insufficient funds")
    return balance - amount
 
try:
    withdraw(50, 100)
except ValueError as e:
    print("Transaction failed:", e)
আউটপুটTransaction failed: Insufficient funds

raise আপনার নিজের কোডকে ইচ্ছাকৃতভাবে একটি এক্সসেপশন তৈরি করতে দেয়, কী ভুল হয়েছে তা ব্যাখ্যা করা একটি মেসেজ সহ।

কাস্টম এক্সসেপশন ক্লাস চ্যালেঞ্জ

কাস্টম এক্সসেপশন ক্লাস
class InsufficientFundsError(Exception):
    pass
 
def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(f"Tried to withdraw {amount}, only {balance} available")
    return balance - amount
 
try:
    withdraw(50, 100)
except InsufficientFundsError as e:
    print(e)
আউটপুটTried to withdraw 100, only 50 available

একটি কাস্টম এক্সসেপশন (Exception থেকে ইনহেরিট করা একটি ক্লাস) কলিং কোডকে শুধু একটি সাধারণ এররের বদলে নাম দিয়ে আপনার নির্দিষ্ট এরর টাইপ ধরার সুযোগ দেয়।

ভিজ্যুয়াল ব্যাখ্যা

💡 এটা কেন কাজ করে?

উপরের ধারণার ব্যাখ্যাটি আবার ধীরে ধীরে, লাইন বাই লাইন পড়ুন — সেখানকার প্রতিটি কিওয়ার্ড উদাহরণের কোডের একটি লাইনের সাথে সরাসরি মিলে যায়। এখনো পরিষ্কার না হলে, এই লেসনে ট্রেসড উদাহরণ থাকলে সেটি এক ধাপ এক ধাপ করে আবার চালিয়ে দেখুন।

🔍 ভেতরে ভেতরে কী ঘটে? (অ্যাডভান্সড)

ভেতরে ভেতরে, Python আপনার সোর্স কোডকে বাইটকোডে কম্পাইল করে এবং একটি ভার্চুয়াল মেশিনে (CPython ইন্টারপ্রিটার) চালায়। ভ্যারিয়েবলগুলো একটি নেমস্পেস ডিকশনারিতে থাকা নাম, যা মেমরিতে থাকা অবজেক্টের দিকে নির্দেশ করে — উপরের ট্রেসারের মেমরি প্যানেলে ঠিক এটাই দেখানো হচ্ছে।

সাধারণ ভুল

✗ সাধারণ ভুল 1

একটি খালি `except:` সবকিছু ধরে ফেলে, টাইপো ও অসম্পর্কিত বাগ সহ, যা সমস্যা ঠিক না করে আড়াল করে রাখে।

✗ এটি এড়িয়ে চলুন
এতে দেখা দেবে ক্র্যাশ নয়, কিন্তু আসল বাগগুলো নিঃশব্দে অলক্ষিত থেকে যায়
try:
    do_something()
except:
    pass
✓ সঠিক পদ্ধতি
সংশোধিত
try:
    do_something()
except ValueError as e:
    print("Invalid value:", e)
✓ ভালো অভ্যাস
  • যত নির্দিষ্ট সম্ভব এক্সসেপশন টাইপ ধরুন — ValueError, খালি except নয়।
  • একটি খালি `pass` দিয়ে কখনো নিঃশব্দে এক্সসেপশন গিলে ফেলবেন না — কমপক্ষে এটি লগ করুন।
  • সাফল্য বা ব্যর্থতা নির্বিশেষে যা ঘটতেই হবে এমন cleanup-এর জন্য finally ব্যবহার করুন (একটি ফাইল বন্ধ করা, একটি রিসোর্স মুক্ত করা)।
  • যিনি এটি ধরবেন তিনি কী ভুল হয়েছে বুঝতে পারেন এমন একটি স্পষ্ট, নির্দিষ্ট এরর মেসেজ দিয়ে raise করুন।

অনুশীলনী ও চ্যালেঞ্জ

অনুশীলনী 1 — কোডের ভুল খুঁজুন

এই কোডটি দেওয়া আছে
try:
    print(10 / 0)
except ValueError:
    print("Cannot divide")

এই কোডটি শূন্য দিয়ে ভাগের এরর ধরার কথা, কিন্তু except ক্লজে ভুল এক্সসেপশন টাইপ ধরা আছে। ValueError-এর বদলে এখানে কী থাকা উচিত?

💡 শূন্য দিয়ে ভাগ করলে একটি নির্দিষ্ট, উপযুক্ত-নামের এক্সসেপশন হয়।

except ZeroDivisionError:

🏆 চ্যালেঞ্জ

safe_divide(a, b) নামে একটি ফাংশন লিখুন যা ভাগের ফলাফল রিটার্ন করে, অথবা b শূন্য হলে একটি বন্ধুত্বপূর্ণ মেসেজ প্রিন্ট করে None রিটার্ন করে।

  • try/except ZeroDivisionError ব্যবহার করুন
  • সাফল্যে হিসাব করা মান রিটার্ন করুন
  • ব্যর্থতায় None রিটার্ন করে একটি মেসেজ প্রিন্ট করুন
💡 ইঙ্গিত প্রয়োজন?

explicit-ভাবে return None লিখলে ব্যর্থতার ক্ষেত্রটি স্পষ্ট হয়।

🔍 একটি নমুনা সমাধান দেখুন
Python
def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        print("Cannot divide by zero.")
        return None
 
print(safe_divide(10, 2))
print(safe_divide(10, 0))

কুইজ

প্রতিটি প্রশ্নের উত্তর দিন, তারপর জমা দিয়ে নিজের স্কোর ও ব্যাখ্যা দেখুন।

1. একটি খালি `except:` (কোনো এরর টাইপ ছাড়া) কী ধরে?

কিছুই না
শুধু ValueError
প্রতিটি ধরনের এক্সসেপশন, এমনকি যেগুলো আপনি প্রত্যাশা করেননি সেগুলোও
শুধু সিনট্যাক্স এরর
একটি খালি except সবকিছু ধরে ফেলে, যা আসল বাগ আড়াল করতে পারে — সবসময় একটি নির্দিষ্ট এক্সসেপশন টাইপ পছন্দ করুন।

2. একটি try/except-এর else ব্লক কখন চলে?

সবসময়
শুধু একটি এক্সসেপশন উঠলে
শুধু কোনো এক্সসেপশন না উঠলে
কখনোই না, এটা বৈধ সিনট্যাক্স নয়
try স্টেটমেন্টের else শুধু try ব্লক কোনো এক্সসেপশন ছাড়া সফল হলেই চলে।

3. finally কখন চলে?

শুধু সাফল্যে
শুধু ব্যর্থতায়
সবসময়, সাফল্য বা ব্যর্থতা নির্বিশেষে
কখনোই না
finally সবসময় চলে, যা এটিকে cleanup কোডের জন্য আদর্শ করে তোলে।

4. raise ValueError("message") কী করে?

একটি সতর্কতা প্রিন্ট করে চলতে থাকে
ইচ্ছাকৃতভাবে সেই মেসেজ সহ একটি এক্সসেপশন তৈরি করে
একটি ফাইলে এরর লগ করে
বর্তমান লাইন উপেক্ষা করে
raise ইচ্ছাকৃতভাবে দেওয়া টাইপের একটি এক্সসেপশন তৈরি করে, একটি ঐচ্ছিক মেসেজ সহ।

সারাংশ

  • try/except এক্সসেপশন ধরে যাতে আপনার প্রোগ্রাম ক্র্যাশ না করে সাড়া দিতে পারে।
  • else শুধু সাফল্যে চলে; finally সবসময় চলে, cleanup-এর জন্য আদর্শ।
  • raise আপনার নিজের কোডকে একটি স্পষ্ট মেসেজ সহ ইচ্ছাকৃতভাবে একটি এক্সসেপশন তৈরি করতে দেয়।
  • যতটা সম্ভব নির্দিষ্ট এক্সসেপশন টাইপ ধরুন।
